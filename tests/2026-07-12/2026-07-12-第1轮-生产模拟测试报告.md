## Findings

### [P2] Style export 的 JSON tokens 与 `.tokens.css` 会在用户改色后分叉

Location:

- `sync_renders.py:2121`
- `sync_renders.py:2126`
- `sync_renders.py:2146`
- `sync_renders.py:2147`
- `sync_renders.py:2158`
- `sync_renders.py:2160`

Reproduction:

1. 打开 `renders/styles/quant-signal-console.html`
2. 将页面 CSS variable `--dig-accent` 修改为 `#C2185B`
3. 点击 Style Lab 的 `Export Style`
4. 解包导出的 `quant-signal-console.customstyle-*.zip`
5. 检查 JSON 中的 `tokens["--dig-accent"]` 与 `css`

Expected:

- `payload.tokens["--dig-accent"]` 为 `#C2185B`
- `payload.css` / `.tokens.css` 也应包含 `--dig-accent: #C2185B;`
- ZIP 内 JSON 与 `.tokens.css` 代表同一个 customstyle source of truth

Actual:

- `payload.tokens["--dig-accent"]` 为 `#C2185B`
- `payload.css` 仍包含原始值 `--dig-accent: #d4485a;`
- `.tokens.css` 使用 `payload.css` 写入，因此也保留旧值

Evidence:

- `tests/2026-07-12/quant-signal-console-customstyle.json`
  - line 29: `"--dig-accent": "#C2185B"`
  - line 93: `--dig-accent: #d4485a;`

Failure mode:

- `buildStyleExportPayload()` 先构造了已合并的 `styleTokens`，但 `styleCss` 仍优先使用原始 `data-style-token-block`。
- 当用户修改当前 render 的 visible token 后，JSON `tokens` 和 ZIP 中 `.tokens.css` 表示不同状态。

Fix direction:

- `styleCss` 应从最终 `styleTokens` 重建，而不是在存在 `styleTokenCss` 时继续使用原始 token block。
- 或至少在合并 `collectStyleTokens()` 后，对 `styleTokenCss` 中同名 token 做覆盖，再生成 `payload.css`。
- 修复后应新增 validator：Style export 改 `--dig-accent` 后，JSON `tokens` 和 `css` 必须一致。
