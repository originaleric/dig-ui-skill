# 2026-06-01 个人 Local 规则跨工具同步落地

## 更新概览

在现有 `dig-ui-skill` CLI 基础上，增加 **用户私有 local 规则跨工具同步** 能力，采用「双通道部署」：

- **仓库通道**：继续只发布共享 skill 资产（`global-rules.md`、示例文件、catalogs 等）。
- **用户通道**：个人 `global-rules.local.md` 放在仓库外配置中心，由 CLI 同步到 Cursor、Codex、Claude Code。

用户配置中心（唯一真源）：

```text
~/.config/dig-ui-skill/global-rules.local.md
```

各工具 skill 目录中的 `references/global-rules.local.md` 仅为同步副本；高级模式下可通过 `--link-local` 软链接到配置中心。

目标同步路径：

```text
~/.cursor/skills/dig-ui/references/global-rules.local.md
~/.codex/skills/dig-ui/references/global-rules.local.md
~/.claude/skills/dig-ui/references/global-rules.local.md
```

本方案是对 `plans/2026-06-01-个人Local规则跨工具同步方案.md` 的落地，补充 `plans/2026-06-01-dig-ui-skill多工具安装与更新CLI方案.md` 中缺失的个人规则跨端一致性能力。

## 详细改动

### 1. CLI 新增命令

扩展 `bin/dig-ui-skill.mjs`，新增三个子命令，并增强 `update` / `status`：

| 命令 | 作用 |
|------|------|
| `init-local` | 从 `references/global-rules.local.example.md` 初始化用户配置；已存在则不覆盖 |
| `sync-local <target>` | 把配置中心 local 规则复制/链接到指定工具 |
| `sync-local --all` | 同步到 Cursor、Codex、Claude Code 三端 |
| `import-local <target>` | 把某工具目录已有 local 规则导入配置中心 |
| `update --with-local` | 更新标准资产后，尝试同步用户 local 规则 |
| `update --with-local --link-local` | 同上，但用 symlink 代替复制 |

常用示例：

```bash
npx dig-ui-skill init-local
npx dig-ui-skill sync-local --all --from-config
npx dig-ui-skill sync-local cursor --from-config
npx dig-ui-skill import-local cursor
npx dig-ui-skill update --all --with-local --from-config
npx dig-ui-skill status
```

### 2. 冲突处理

当配置中心与目标工具目录 **同时存在** `global-rules.local.md` 且 **内容不同** 时，采用 **safe-by-default** 策略：

| 场景 | 行为 |
|------|------|
| 目标尚无 local 文件 | 从配置中心复制/链接，无需额外 flag |
| 内容与配置中心一致 | 跳过，报告 already in sync |
| 内容不同（默认） | **报告冲突，不覆盖** |
| `--from-config` | 显式用配置中心覆盖目标 |
| `--from-target` | 显式把目标 local 文件导入为配置中心主版本 |
| `--backup` | 覆盖前生成 `.backup` 文件 |
| `--skip-conflicts` | 跳过冲突目标，继续处理其他工具 |

> 不依赖 `mtime` 判断新旧，避免复制/解压等操作导致误覆盖用户在目标目录的手动修改。

### 3. 与 install / update 的协作

- `install` / `update` 继续 **永不覆盖** 目标目录已有 `references/global-rules.local.md`。
- 只有显式 `--with-local` 或执行 `sync-local` 才从配置中心同步。
- `update --with-local` 在内容不一致时同样遵循冲突策略，需加 `--from-config` 才会覆盖目标。
- 配置中心不存在时，提示运行 `init-local`，不自动创建个人偏好。
- `install` 完成后的 tip 改为指向 `init-local` / `sync-local --from-config`。

### 4. status 增强

`status` 新增用户配置中心区块，并显示各端 local 规则与配置中心的同步关系：

- `linked to user config` — 已软链接到配置中心
- `in sync with user config` — 内容与配置中心一致
- `present (differs from user config)` — 存在但与配置中心不一致

### 5. 文档更新

- `INSTALL.md`：补充配置中心工作流、冲突处理选项、`--link-local` / `--with-local` 说明。
- `references/global-rules.local.example.md`：推荐使用 `init-local` + `sync-local --all --from-config` 管理个人规则。

## 运维工作流

```text
1. 首次配置：  npx dig-ui-skill init-local
2. 首次同步：  npx dig-ui-skill sync-local --all --from-config
3. 日常更新：  npx dig-ui-skill update --all --with-local --from-config
4. 检查状态：  npx dig-ui-skill status
5. 从某端导入：npx dig-ui-skill import-local cursor
```

编辑个人规则后，只改配置中心文件，再 **显式推送**：

```bash
# 编辑 ~/.config/dig-ui-skill/global-rules.local.md
npx dig-ui-skill sync-local --all --from-config
```

本机开发调试可使用软链接模式，避免重复复制：

```bash
npx dig-ui-skill sync-local --all --link-local
```

## 验证清单

验收环境：macOS，Node.js 本地 CLI（`node bin/dig-ui-skill.mjs`），已安装三端 skill 目录。

| 检查项 | 预期结果 | 验证命令 |
|--------|----------|----------|
| `init-local` 只在配置目录创建文件 | `~/.config/dig-ui-skill/global-rules.local.md` 存在，仓库内无新增 | `node bin/dig-ui-skill.mjs init-local --source .` |
| `init-local` 不覆盖已有文件 | 输出 Already exists，内容不变 | 再次执行 init-local |
| 首次 `sync-local --from-config` | 三端出现与配置中心相同内容 | `node bin/dig-ui-skill.mjs sync-local --all --from-config` + `diff` |
| 修改配置中心后无 flag 同步 | 报告 conflict，目标不被覆盖 | 编辑配置中心 → `sync-local cursor`（exit code 1） |
| 修改配置中心后 `--from-config` | 三端内容与配置中心一致 | `sync-local --all --from-config` |
| 目标目录手动改动后默认同步 | 报告 conflict，不覆盖 | 改写目标 local → `sync-local cursor` |
| `--backup --from-config` | 生成 `.backup` 且目标被覆盖 | `sync-local cursor --from-config --backup` |
| `import-local` | 配置中心内容与目标一致 | `import-local cursor` |
| 普通 `update` | 不覆盖目标 local 文件 | `update cursor --source .` |
| `status` | 显示配置中心与各端同步状态 | `node bin/dig-ui-skill.mjs status` |

## 价值与影响

- **跨端一致**：Cursor、Codex、Claude Code 共用同一份个人规则，无需手动复制三份。
- **仓库干净**：个人偏好不进 git，配置中心在 `~/.config/` 统一管理。
- **更新安全**：标准资产可刷新，local 规则默认受保护；覆盖需显式 `--from-config` / `--from-target`。
- **迁移友好**：`import-local` 支持从已有工具目录导入，平滑过渡到配置中心模式。

本次 **未改动** catalog / layout 渲染链、Global Rules 源文件与品牌 preview；为 CLI 安装分发层的增量补充。
