# 2026-07-23 Style 目录扩展与双主题预览闭环

## 背景

Style catalog 已经是与 brand catalog、color palette catalog 并列的基础视觉线，但此前内置 style 覆盖有限，且 light/dark token 只有文档和导出层面的约定，未形成可切换、可验证、可再导入的完整闭环。

## 变更

- 内置 style 从 2 条扩展到 12 条，新增：
  - `strategy-report`
  - `research-lab`
  - `brick-builder`
  - `archive-dotmatrix`
  - `concept-minimal`
  - `semantic-translation`
  - `business-editorial`
  - `torn-editorial-collage`
  - `midcentury-noir`
  - `cel-sci-fi`
- 新增 `references/catalogs/styles/README.md`，按适用任务、avoid 边界和 render archetype 路由 style 选择，避免把 brand、palette 与 style 混成多个基础系统。
- `style_v1` 增加正式 dual-theme contract：light/dark 都覆盖核心 surface、text、border、control 与 semantic-state token。
- Style Lab 导出 `theme_tokens.light`、`theme_tokens.dark`、light token CSS 与 dark token CSS；导出 parser 支持一行多个 CSS token 声明，导出的资产可被 CLI 再导入。
- Style render 具备 token-only 的 light/dark 切换、用户偏好持久化、键盘 focus 状态和幂等生成保护；重复同步不会重复追加 dark override。
- `style_v1` Markdown 导入强制要求 light/dark 两个 token block。旧版 JSON customstyle 保持兼容导入，但不被视为双主题事实源。
- 新增 `strategy-workspace`、`research-workbench`、`builder-journey`、`editorial-story` 四种 render archetype，并为全部新增样张补齐中英双语文案。
- `midcentury-noir` 与 `cel-sci-fi` 补齐独立的 light token map，避免两个主题仅名义不同。

## 文档同步
