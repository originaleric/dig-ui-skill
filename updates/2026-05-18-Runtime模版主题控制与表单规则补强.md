# 2026-05-18 Runtime 模版主题控制与表单规则补强

## 更新概览

本次更新围绕 `dig-ui-skill` 的 `runtime` 基础模版进行补强，重点解决真实产品界面落地时常见的三个问题：主题切换缺少 token 约束、语言切换缺少 chrome 规范、表单控件在 dark/light 下容易出现颜色与形态不一致。

同时，根目录 `README.md` 新增了 `tokens.md` 总规范与单个 catalog 扩展之间的关系说明，明确当前设计系统不是“每个模版拆成两个 md”，而是采用“全局 token 协议 + 单个 catalog 落地扩展”的两层结构。

## 详细改动

1. **补充 Runtime 主题 token 规则**
   - 在 `references/catalogs/other/runtime.md` 的颜色 token 中新增 `--dig-control-bg` 与 `--dig-control-bg-hover`。
   - 明确 runtime 默认优先 dark，但必须提供 `dark` / `light` 两套模式。
   - 规定 dark/light 只替换 token 值，不改变组件语义，避免在组件里写死暗色或亮色。
   - 特别约束表单、select、控制条必须引用 `--dig-control-bg` / `--dig-control-bg-hover`，不能继续使用固定暗色 `rgba(5, 18, 27, ...)`。

2. **固化表单与 select 的药丸形态**
   - 在 `间距与圆角` 中新增规则：`input`、`select trigger`、`select option` 使用 `var(--dig-radius-pill)`。
   - 在 `Components Strict Mapping` 中新增 `form-input`、`select-trigger`、`select-menu`、`select-option`、`select-option-active`。
   - 该规则用于保证 runtime 产品界面中的表单控件与 header 控制条拥有一致的胶囊语言，同时避免 light 模式下出现暗色硬编码残留。

3. **新增 Runtime Header Chrome 控制规范**
   - 在 `Components Strict Mapping` 中新增 `segmented-control`、`segmented-control-item`、`segmented-control-item-active`。
   - 新增 `theme-mode-control`，约定 `dark` / `light` 使用 segmented pill 控制，图标使用 lucide-line 风格，并支持持久化。
   - 新增 `language-control`，约定 `zh-CN` / `en` 使用 segmented pill 控制，中文可显示 `中`，英文显示 `EN`。
   - 规定 header / topbar 中的模式切换与语言切换优先放在右上角，与导航 pill 同组，但视觉层级不能抢主 CTA。

4. **新增 Runtime Chrome 与 i18n 行为小节**
   - 新增 `Runtime Chrome 与 i18n` 小节，明确语言切换、主题切换、文案来源和持久化方式。
   - 规定 i18n 文案必须来自语言包，不要在组件中混写中英文常量。
   - 至少应覆盖导航、主标题、表单 label、按钮、状态与错误提示。
   - 切换语言时必须同步更新 `document.documentElement.lang`，并持久化到 localStorage 或等价用户设置。

5. **补充交互规则**
   - 明确 `input`、`select trigger`、`select option` 的 hover/focus 只改变 border、background、glow，不改变高度、padding 或圆角。
   - 明确 segmented control 的 active 状态使用 accent 填充，inactive hover 只提高文字对比或轻微背景，不产生布局跳动。

6. **更新 README 架构说明**
   - 在 `README.md` 新增 `Token 总规范与 Catalog 扩展` 小节。
   - 明确 `references/tokens.md` 是全局字段协议，`references/primitives.md` 是基础 primitive 规则，`references/catalogs/**/<name>.md` 是具体 catalog 模版。
   - 说明每个 catalog 仍然是一个独立 md，不需要拆成两个文件。
   - 说明每个 catalog 可以定义自己的 attribute / component mapping，但通用字段应尽量复用 `tokens.md`，专属能力写在 catalog 内。

## 价值与影响

本次更新把真实业务落地中反复出现的“暗色硬编码”“light 模式失真”“表单控件形态不统一”“中英文混写”“header 控制缺少规范”等问题，沉淀为 runtime catalog 的结构化规则。

后续 AI Agent 调用 `dig-ui-skill` 生成 runtime / dashboard / console 类产品界面时，将更容易默认产出：

- 支持 dark/light 的 token 化界面；
- 右上角具备一致的主题与语言 segmented control；
- input/select 采用统一药丸形态；
- i18n 文案从语言包读取；
- 组件 hover/focus 不发生尺寸跳动。

这让 `runtime` 不再只是配色模版，而是更接近一套可落地到真实产品的 Dig 运行时界面协议。
