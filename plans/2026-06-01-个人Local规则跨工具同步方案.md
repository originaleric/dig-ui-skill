# 个人 Local 规则跨工具同步方案

## Summary

为 `dig-ui-skill` 增加一套用户私有规则同步机制：仓库继续只发布共享规则与示例文件，用户自己的 `global-rules.local.md` 不进入仓库，而是放在仓库外的用户配置目录中，再由 CLI 同步到 Cursor、Codex、Claude Code 等目标 skill 目录。

## Problem

`references/global-rules.local.md` 的设计目标是承载每个用户自己的规则偏好，因此不应该被 push 到仓库。

但如果只用仓库部署文件安装或更新 skill，就只能同步仓库内的标准资产，无法把用户自己的 local 规则一起部署到目标工具目录。结果是：

- Cursor、Codex、Claude Code 的 local 规则容易不一致。
- 用户需要手动复制 `global-rules.local.md`。
- `install` / `update` 如果直接覆盖 local 文件，又会破坏“用户私有偏好”的设计。

## Recommended Design

采用“双通道部署”：

- 仓库通道：发布共享 skill 资产。
- 用户通道：同步用户私有 local overlay。

仓库内只保留：

- `references/global-rules.md`
- `references/global-rules.local.example.md`
- `SKILL.md`
- catalogs / layouts / tokens / assets 等标准文件

用户自己的规则统一放到仓库外：

```bash
~/.config/dig-ui-skill/global-rules.local.md
```

这个文件作为用户私有规则的唯一真源。各工具目录里的 `references/global-rules.local.md` 只是同步副本，或在高级模式下作为软链接。

## Target Paths

用户配置中心：

```bash
~/.config/dig-ui-skill/global-rules.local.md
```

目标工具目录：

```bash
~/.cursor/skills/dig-ui/references/global-rules.local.md
~/.codex/skills/dig-ui/references/global-rules.local.md
~/.claude/skills/dig-ui/references/global-rules.local.md
```

## CLI Commands

建议在现有 `dig-ui-skill` CLI 方案中增加这些命令与参数：

```bash
dig-ui-skill init-local
dig-ui-skill sync-local cursor
dig-ui-skill sync-local codex
dig-ui-skill sync-local claude-code
dig-ui-skill sync-local --all
dig-ui-skill update --all --with-local
dig-ui-skill update --all --with-local --link-local
dig-ui-skill import-local cursor
```

命令语义：

- `init-local`：从 `references/global-rules.local.example.md` 初始化 `~/.config/dig-ui-skill/global-rules.local.md`；如果文件已存在则不覆盖。
- `sync-local <target>`：把用户配置中心的 local 规则复制到指定工具目录。
- `sync-local --all`：同步到 Cursor、Codex、Claude Code。
- `update --with-local`：更新共享 skill 资产后，同步用户 local 规则。
- `--link-local`：用 symlink 代替复制，让目标工具直接指向用户配置中心文件。
- `import-local <target>`：把某个工具目录里已有的 `global-rules.local.md` 导入为用户配置中心主版本。

## Update Rules

`install` / `update` 的默认行为：

- 覆盖仓库标准资产，例如 `SKILL.md`、`references/global-rules.md`、catalogs、layouts、tokens、assets。
- 永远不覆盖目标地已有的 `references/global-rules.local.md`。
- 如果用户配置中心存在 local 文件，只有显式传入 `--with-local` 或执行 `sync-local` 才同步。
- 如果用户配置中心不存在 local 文件，可以提示运行 `dig-ui-skill init-local`，但不要自动创建个人偏好。

## Conflict Handling

当用户配置中心和目标工具目录都存在 `global-rules.local.md`，且内容不同：

- 默认不覆盖，提示存在冲突。
- 支持用户明确选择：
  - `--from-config`：用 `~/.config/dig-ui-skill/global-rules.local.md` 覆盖目标地。
  - `--from-target`：把目标工具目录的 local 文件导入为配置中心主版本。
  - `--backup`：覆盖前生成 `.backup` 文件。
  - `--skip-conflicts`：跳过冲突目标，继续处理其他工具。

## Default Recommendation

默认使用复制模式，不使用 symlink：

```bash
dig-ui-skill update --all --with-local
```

复制模式对 Cursor、Codex、Claude Code 更稳定，也更容易理解和排查。

高级用户或本机开发调试可以使用：

```bash
dig-ui-skill update --all --with-local --link-local
```

## Test Plan

- 运行 `dig-ui-skill init-local`，确认只在 `~/.config/dig-ui-skill/` 创建 local 文件，不写入仓库。
- 运行 `dig-ui-skill sync-local --all`，确认三端目标目录都出现相同的 `references/global-rules.local.md`。
- 修改用户配置中心 local 文件后再次同步，确认三端内容更新一致。
- 在目标目录制造不同内容的 local 文件，确认默认不覆盖并提示冲突。
- 使用 `--backup --from-config` 覆盖冲突文件，确认备份文件存在。
- 运行普通 `dig-ui-skill update --all`，确认不会覆盖任何 local 文件。
